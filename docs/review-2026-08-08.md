# Milcah — functional and code review

**Date:** 2026-08-08 · **Reviewed:** `master` @ `e729069`, version **0.4.0**
(clean working tree)
**Method:** the pipeline was exercised end to end on a purpose-built framework
document (`extract` → `ontology` → `metrics`, plus `specialist`), then the source
was read. Every claim below is backed by a run or a probe, reproduced inline.

> **Follow-up (0.5.0):** actioned H1–H4, F1–F5, M1–M4, L1–L2. Deferred: M5 DNS

## Part 1 — Functional review

**Baseline:** `148 passed` in 0.79 s. `ruff check src tests` clean, rule set
pinned (`select = ["E4","E7","E9","F"]`) with the explanatory comment. CI runs
both.

> On a fresh checkout the suite reports `2 failed` — `test_version.py` and
> `test_smoke.py` compare `milcah.__version__` against `pyproject.toml`, and a
> stale editable install (0.3.2 dist-info vs 0.4.0 source) fails them. `pip
> install -e . --no-deps` restores green. CI installs fresh, so CI is unaffected.

### What works — including one thing better than anywhere else in the estate

The pipeline runs cleanly and the philosophy is enforced *structurally*, not just
documented: `metrics.py:33` declares
`EXCLUDED_SIGNALS = ("popularity", "confidence", "institutional_acceptance", "model_agreement")`
and the deterministic placement function carries a comment explaining that it
deliberately consumes no consensus signal so the metrics stay free of
popularity. Multi-LLM reconciliation records `agreement` / `consensus` /
`type_votes` as *provenance* and never folds them into a score. That is the
stated philosophy actually holding in code.

**`web_research.py:70-118` is the best SSRF guard in the estate** and is worth
copying into Hoglah and Tirzah, both of which have weaker versions:

```python
if parsed.scheme not in {"http", "https"} or not parsed.hostname: raise …
if parsed.username or parsed.password: raise …            # credential URLs refused
if any(not ipaddress.ip_address(a).is_global for a in addresses): raise …

class _SafeRedirectHandler(request.HTTPRedirectHandler):
    def redirect_request(self, req, fp, code, msg, headers, newurl):
        _public_url(newurl, allow_private_hosts=self.allow_private_hosts)   # every hop
        return super().redirect_request(...)
```

`is_global` is stricter than the `is_private or is_loopback or …` enumeration
used elsewhere, and **re-checking each redirect hop** is exactly the gap flagged
as Hoglah M9 and Tirzah M9. Milcah already fixed it.

`milcah serve` binds `127.0.0.1` by default, is read-only, and says so in its own
docstring — no Tirzah-style exposure problem here.

### Functional defects

#### F1. `global_coherence` is 1.0 for everything on the default path

This is the headline number of a product called the Coherence Engine. Measured
across five inputs through the real `ingest → extract → build_ontology →
compute_metrics` path:

```
input                           coherence  fracture  uncert  placement states
sound syllogism                       1.0       0.0     0.0  {'resolved': 3}
ad hominem + non sequitur             1.0       0.0     0.0  {'resolved': 3}
assumption-heavy                      1.0       0.0     0.0  {'resolved': 3}
pure nonsense                         1.0       0.0     0.0  {'resolved': 4}
contradiction                         1.0       0.0     0.0  {'resolved': 3}
```

"All swans are white. This swan is black. Therefore all swans are white." scores
a perfect 1.0, as does "Purple. Seventeen. The moon is a committee. Therefore."

On the review's own test framework — which contains an ad hominem ("Anyone who
disagrees has not read the research"), poisoning the well ("funded by commercial
landlords"), an appeal to obviousness, and a non-sequitur — `milcah metrics`
returned:

```
global_coherence: 1.0     fracture_density: 0.0     uncertainty_burden: 0.0
fallacy_load: 0
```

The score *can* fall below 1.0, but only one way — see H1. Root cause and the
precise failure mode there.

#### F2. The rule-based classifier mistypes on substring collisions and inverts on negation

Two sentences of identical grammatical form, both opening "We assume that…":

```
observation  markers=['measured']  <- We assume that measured output captures what matters about work.
assumption   markers=['assume']    <- We also assume that what held during a pandemic holds…
```

The first is typed an **observation** because `"measured"` sits in a
higher-priority marker list than `"assume"`.

Negation is not handled at all, so a sentence that *denies* a reasoning role is
typed as having it:

```
commitment   markers=['necessarily']  <- This does not necessarily follow from the premise.
primitive    markers=['axiom']        <- That is not an axiom, it is a conjecture.
assumption   markers=['assume']       <- I never assume the reader knows this.
observation  markers=['measured']     <- The claim was not measured against any baseline.
```

And incidental everyday use captures the type:

```
enthymeme    markers=['clearly']   <- The label is clearly printed on the box.
bridge       markers=['so that']   <- We moved the desk so that the cable reached.
bridge       markers=['because']   <- She left because it was raining.
conclusion   markers=['ultimately'] <- Ultimately it comes down to taste, but let us continue.
```

Typing "this does not necessarily follow" as a **commitment** is a semantic
inversion at the base of the pipeline — everything downstream (ontology
placement, metrics, the five-questions recursion) inherits it.

#### F3. The sentence splitter fragments ordinary prose

```
"Dr. Smith disagrees. He cites Fig. 3 and p. 12."
  → ['Dr.', 'Smith disagrees.', 'He cites Fig.', '3 and p.', '12.']   (5 units)
"Use e.g. remote work. It works."
  → ['Use e.g.', 'remote work.', 'It works.']                         (3 units)
```

Each fragment becomes a reasoning unit and an ontology node, so `node_count`,
`breadth`, `ontological_completeness`, `fracture_density` and `uncertainty_burden`
all have punctuation-inflated denominators. Every metric in FR7/FR9 is computed
over a node count that depends on how many abbreviations the author used.

#### F4. The specialist boundary discards the failure reason

The Tirzah↔Milcah contract, with the Hoglah extractor unavailable:

```json
{ "terminal_reason": "blocked",
  "trace_metadata": { "validation_errors": ["HoglahExtractionError"], "mode": "coherence" },
  "error": null, "error_type": null,
  "confidence": 0.0, "confidence_bands": null }
```

The envelope has dedicated `error` / `error_type` fields — added precisely
because the consumer carried them and the provider did not — and the provider's
failure path leaves both `null`. Only the exception **class name** survives;
`str(exc)` is thrown away (`specialist.py:109`). A caller cannot distinguish "no
Hoglah daemon" from "model not pulled" from "job timed out".

`confidence: 0.0` with `confidence_bands: null` compounds it: the envelope models
`unassessed` as distinct from `low` specifically so a failed run is not read as a
confident zero, and the blocked path uses neither.

#### F5. No test exercises any LLM path, at any level

148 tests in **0.79 seconds**, and:

```
$ grep -rn "skipif\|pytest.skip\|RUN_" tests/
(no matches)
```

There is not one skip-guarded live test. Every model, Hoglah and Mongo
interaction is faked. Hoglah gates its live tests behind `RUN_*_TESTS`; Tirzah
runs against live MongoDB. Milcah has no opt-in path at all, so the quality path
the README recommends (`--extractor hoglah`, `--models a,b,c`, `--reconcile
semantic`) has never been executed by a test on any commit.

## Part 2 — Code review

### High

#### H1 · `metrics.py:86` + `ontology.py:126-137` — `global_coherence` measures "fraction of nodes not under a *therefore*"

```python
global_coherence=round(resolved / n, 3),
```

`resolved` counts ontology nodes whose **placement state** is `RESOLVED`. On the
deterministic path — the default, and the only one that runs without a model —
`_placement` can return just three things:

```python
if node.parent_id and nodes[node.parent_id].type in _BRIDGES:
    return PlacementState.DEPENDENT_ON_UNRESOLVED_BRIDGE
if node.type == ReasoningUnitType.ENTHYMEME:
    return PlacementState.PARTIALLY_RESOLVED
return PlacementState.RESOLVED
```

and `PARTIALLY_RESOLVED` is counted as unresolved only if `resolved` excludes it.
In practice the score is driven entirely by the first branch. Demonstrated:

```
"Therefore A. Therefore B. Therefore C. Therefore D."   coherence = 0.25
"All swans are white. This swan is black.
 Therefore all swans are white."                        coherence = 1.00
```

Content-free text scores worst; a self-contradiction scores best. The metric is
**inversely** related to argument quality in the constructed case, because
writing explicit reasoning connectives is what lowers it.

The module comments are honest that structural placement is a scaffold and that
the rich states (`multiple_placement_candidates`, `contradictory_placement`) come
from the LLM pass. The problem is presentation: `milcah metrics` prints
`global_coherence: 1.0` under the heading "coherence (FR9)" with no indication
that the number is degenerate on the path that just ran.

This also explains an earlier estate observation — a Milcah specialist experiment
that returned `confidence: 0.143` **constant** across five runs with visibly
different outputs. That value derives from `global_coherence`, i.e. from graph
shape, not from anything about the answers.

**Fix, in order of cost:** (1) have `milcah metrics` refuse to print
`global_coherence` when every node is `RESOLVED` and no reasoned placement pass
ran, or label it `structural_placement_ratio`; (2) rename the field to what it
measures; (3) populate the real placement states.

#### H2 · `extraction.py:29-77` — unanchored substring matching with a fixed type priority and no negation handling

```python
def classify_sentence(sentence: str) -> tuple[ReasoningUnitType, list[str]]:
    lowered = sentence.lower()
    for unit_type, markers in _MARKER_RULES:
        hit = [m for m in markers if m in lowered]
        if hit:
            return unit_type, hit
    return ReasoningUnitType.CLAIM, []
```

Code side of F2. Three compounding issues: `m in lowered` is unanchored (so
`"measured"`, `"because"`, `"axiom"`, `"clearly"` match anywhere in a sentence);
the first matching *list* wins regardless of where in the sentence its marker
appeared (so a mid-sentence `"measured"` beats a sentence-initial `"assume"`);
and there is no negation or scope analysis, so `not`/`never` before a marker
inverts the meaning while keeping the type.

**Fix:** anchor markers to word boundaries and, where the marker is positional
("in conclusion", "therefore"), to sentence-initial position; prefer the
**earliest** match rather than the highest-priority list; and treat a negation
within a small window before the marker as a non-match.

This is the third instance of the same family in this estate — Hoglah's
`classify_error` and Deborah's `re.I` construct matcher are the other two.

#### H3 · `extraction.py:63` — `_SENTENCE_SPLIT` splits on any `.` followed by whitespace

```python
_SENTENCE_SPLIT = re.compile(r"(?<=[.!?])\s+")
```

Code side of F3. Every abbreviation, initial, and numbered reference produces a
spurious unit. Decimals survive only by accident (no space after the point).

**Fix:** a negative lookbehind for common abbreviations and single capitals, or a
small sentence splitter. Given every FR7/FR9 denominator depends on it, this is
cheap insurance.

#### H4 · `specialist.py:109` and `:186-189` — the provider boundary drops the message and leaves the envelope's error fields empty

```python
except Exception as exc:  # provider boundary: callers get a terminal reason
    return _blocked([type(exc).__name__], request=req)
…
trace_metadata: dict[str, Any] = {"validation_errors": errors}
return SpecialistResult(terminal_reason="blocked", trace_metadata=trace_metadata)
```

Code side of F4. Not leaking exceptions across the boundary is right; discarding
`str(exc)` is not. And `SpecialistResult` has `error` / `error_type` for exactly
this and neither is set.

Worth noting this is the **third link in a chain of swallows**. Traced end to end:

```
hoglah/client.py:1041   error="Unexpected worker error"   ← real exception → logger only
milcah/hoglah_extractor  wraps it as HoglahExtractionError("Unexpected worker error")
milcah/specialist.py:109 keeps only "HoglahExtractionError"
```

By the time Tirzah sees it, three layers of cause have been replaced by a class
name. Setting `error=str(exc)` and `error_type=type(exc).__name__` here recovers
one of them for free.

### Medium

#### M1 · `metrics.py:85` — `fallacy_load` is structurally always 0 in `milcah metrics`

```python
fallacy_load=sum(len(node.metadata.get("fallacies", [])) for node in nodes),
```

The field's own comment says "if marked onto the ontology". `milcah metrics`
builds the ontology fresh from extraction and no code path marks fallacies onto
it, so the explanatory-debt report always shows `fallacy_load: 0` — including on
a framework where `milcah fallacy` would find several. The one debt component
that measures reasoning quality rather than shape is inert in the command that
reports debt.

#### M2 · `ingestion` / `extraction` — markdown structure is not stripped

`"# The productivity thesis"` is extracted as a `claim` and becomes a root
ontology node. Headings, list bullets and code fences all enter the reasoning
graph as units. Since the README's first example is `milcah extract
framework.md`, markdown is the expected input format.

#### M3 · `pyproject.toml` — floor-only pin on a fast-moving sibling

`hoglah = ["hoglah>=0.8.0"]` with no upper bound, against a sibling currently at
0.10.4 that has had behaviour-affecting changes in that range. This venv in fact
has **0.7.0** installed, violating the declared floor — an environment artefact
rather than a repo bug, but it is why the Hoglah path failed during this review,
and it is the same version-skew shape that previously caused cost data to be
silently recorded as zero. Consider `>=0.10.4,<0.11`.

#### M4 · `tests/` — the covering tests assert the implementation, not the semantics

`test_extraction.py:13-24` checks eight sentences each constructed to contain
exactly one marker in canonical position. There is no negation case, no
two-marker collision, no incidental use — i.e. no case where the marker table
could be *wrong*. `test_split_sentences` asserts `"One. Two! Three?"` and nothing
harder.

`test_metrics.py:25-45` builds an ontology **by hand** with all five placement
states and checks the arithmetic thoroughly (good). But the only test that runs
the real `build_ontology` path is `test_metrics_from_built_ontology_all_resolved`
(line 59-62), which asserts `global_coherence == 1.0` on a single node — pinning
the degenerate behaviour of H1 in place as expected.

**Fix alongside H1/H2:** add adversarial cases — the negation set above, the
`"We assume that measured…"` collision, and a test asserting that a
self-contradicting framework does **not** score 1.0.

#### M5 · `web_research.py:70-88` — the (otherwise excellent) SSRF guard has a TOCTOU window

`getaddrinfo` resolves and screens, then `opener.open()` resolves again. A DNS
rebind between the two passes the check. Genuinely hard to close without a custom
connector that pins the validated address, and low-priority for a
locally-operated tool — recorded so the strength of the rest of the guard is not
mistaken for completeness.

### Low

#### L1 · `tests/test_version.py:27` — the test's own premise is wrong

```python
"""Guards the other direction: bumping pyproject must be all it takes."""
assert milcah.__version__ == declared
```

Bumping `pyproject.toml` is *not* all it takes: `__version__` reads installed
package metadata, so every local version bump red-lights the suite until the
developer reinstalls. Either compare against the source of truth directly, or
skip when the install is editable and stale.

#### L2 · `metrics.py:88` — `ontological_completeness` is a foundation ratio, not completeness

`foundations / n` fell to `0.125` on the review framework while every node was
simultaneously reported `resolved`. Two metrics named for the same underlying
idea disagreeing by an order of magnitude is confusing in a report meant for
humans; the name promises more than a type-count ratio delivers.

## Comparison with the Hoglah, Deborah and Tirzah reviews

Milcah is the cleanest codebase of the four on structure and the most rigorous on
philosophy-in-code — and it has the estate's single worst *semantic* defect,
which is an unusual combination worth naming.

The shared failure family is now confirmed in all four repos: **unanchored
substring matching standing in for a structured signal.**

| repo | where | consequence |
|---|---|---|
| Hoglah | `classify_error` on exception text | permanent errors retried, real OOM missed |
| Deborah | `re.I` construct match on prose | steps re-typed, first word deleted |
| Tirzah | *(avoided — `re.escape` used correctly)* | — |
| **Milcah** | `classify_sentence` marker `in` | reasoning units mistyped, negations inverted |

And the second family, also now in three of four: **a headline metric that cannot
vary.** Hoglah's Prometheus counters are structurally always zero in both
documented read paths; Milcah's `global_coherence` is structurally 1.0 on the
default path. In both cases the module docstring is honest about the limitation
and the user-facing surface is not.

The distinctive thing about Milcah is that its defects are all in the
**deterministic scaffold that the docs already describe as a scaffold** — and
that scaffold is nonetheless what runs by default, what the README's first
example invokes, and what feeds a `confidence` number consumed by other products
in the estate. The gap is not between what the code does and what it claims; it
is between what the docs qualify and what the CLI prints.

## Suggested order

1. **H1** — either rename `global_coherence` to what it measures or suppress it
   when no reasoned placement pass ran. Nothing else matters while the headline
   number is a constant, and it is currently feeding confidence values elsewhere.
2. **H2 + H3** — anchor the markers, handle negation, fix the splitter. Land with
   the M4 adversarial tests in the same commit so the fix is pinned.
3. **H4** — two extra fields on the blocked path; also worth raising the Hoglah
   side (`client.py:1041` replacing the real exception with a fixed string).
4. **M1, M2** — `fallacy_load` wiring and markdown stripping.
5. **F5/M3** — an opt-in live path (`RUN_HOGLAH_TESTS=1`) and a tighter Hoglah
   pin. The recommended quality path has no executed coverage anywhere.
6. **M5, L1, L2** — small.

Nothing here is architectural. The engine's shape is right, the sibling
boundaries are clean, the philosophy is genuinely enforced in code, and the SSRF
guard should be lifted into the other two repos as-is.
